TECHNIQUE 03 / 11Collaborative

Yes And Building

A chain of accepted additions, never negated. One idea about noticing a repeated request grows, link by link, into a whole trust-and-transparency system for automation.

The agent notices a repeated request and offers to automate it.

yes, and…

it shows the exact ncl tasks create command before confirming.

yes, and…

the user can edit the cadence in plain language and get it re-rendered.

yes, and…

once accepted, it logs which chat message triggered the task — for a later "why do I get this."

yes, and…

after N runs it asks "still useful?" instead of running forever silently.

yes, and…

that self-check generalizes into a staleness flag on any recurring task, computed rather than stored.

yes, and…

the household group gets a monthly digest of everything being quietly tracked, for trust.

yes, and…

the digest lists exactly what to say to turn any given automation off.

yes, and…

the digest is itself produced by an ncl task — dogfooding the very mechanism it explains.

yes, and…

a first-run version of the digest ships the day any automation is created — not just monthly.

TECHNIQUE 06 / 11Invented · unscoped

Ghost User Interview

A skeptical, tired end-user narrates their day using the product out loud. Every complaint gets mined for a fix.

why do I have to say "ncl" anything, I don't even know what that is
Response Never require CLI vocabulary from the user; the agent silently translates asks into task creation.
it filled the form but I don't know which version is real now
Response Proactively surface version history in chat when overwriting, not just on request.
I sent a voice note about groceries and it just did nothing
Response Audit that every attachment type gets an acknowledgment, even when the ask is ambiguous.
why doesn't the household bot know what Yulanda already told me
Response A lightweight cross-group delegation query — not a full memory merge.
I said cancel everything and it asked me sixteen questions
Response A panic-button bulk action that skips per-item confirmation on an explicit bulk request.

TECHNIQUE 08 / 11Invented · spirit of Constraint

One Sentence Spec

Every new capability must fit one plain sentence a non-technical user would actually say. Six notes stuck to the board.

"Tell me what I forgot before I leave the house."
Daily pre-departure checklist synthesized from calendar + open document asks.
"Don't make me repeat myself to a different bot."
Shared fact resolution across the three groups — promoted from pitfall to real initiative.
"Let me undo the last thing you did."
A generic last-action undo, one command, mirrors the proven calendar confirm/delete UX pattern.
"Tell me when you're not sure, don't guess."
A uniform low-confidence disclosure rule across all tools, not just guest resolution.
"Let me ask any of my bots and get the same right answer."
Shared-fact resolution again — reinforced as the clear cross-cutting theme.
"Never surprise me with a reminder I don't remember asking for."
Promotes the receipts / why idea from joke to real spec candidate.

The Recipe That Emerged

Eleven techniques, one long night of reuse and absurdity and quiet honesty about a tired user's day. Boiled down, the same five flavors kept coming back — sometimes as a joke, sometimes as a walk-back, sometimes twice in the same technique.

Shared-fact / context resolution across the three agent groups

Independently reinvented four separate times — the strongest, most-repeated signal in the whole session. Yulanda, the household group, and Tina are isolated on purpose, but the ideas kept asking the same question: why should a fact told to one bot be a stranger to the other two.
