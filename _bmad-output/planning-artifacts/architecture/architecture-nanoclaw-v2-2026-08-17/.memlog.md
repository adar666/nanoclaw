- (decision) AD-15 (self-found post-finalize, self-resolved -- automator authority, obvious fix, no genuine ambiguity): AD-6's raw-fetch decision has a real, previously-unchecked TLS-trust gap. The OneCLI SDK's applyContainerConfig (verified: node_modules/.pnpm/@onecli-sh+sdk@2.2.1/.../lib/index.js) sets SSL_CERT_FILE and DENO_CERT env vars for the gateway's injected CA cert, but never NODE_EXTRA_CA_CERTS -- and Bun's fetch() (confirmed via Bun's own docs/issue tracker, web search) only reads NODE_EXTRA_CA_CERTS for custom CA trust, not SSL_CERT_FILE. Nothing in container-runner.ts or the Dockerfile sets NODE_EXTRA_CA_CERTS either. Left as-is, every calendar fetch() call through the gateway's MITM proxy would very likely fail TLS verification (UNABLE_TO_GET_ISSUER_CERT_LOCALLY or equivalent) -- this is exactly why the one existing gateway-proxied precedent (upload-trace.ts) uses curl (which does honor SSL_CERT_FILE) instead of fetch. Fix: at agent-runner startup (before any calendar tool call), set process.env.NODE_EXTRA_CA_CERTS ??= process.env.SSL_CERT_FILE when the latter is present -- a small, defensive, harmless-if-unneeded shim that closes the gap without abandoning AD-6's fetch()-based design or falling back to curl. Binds CAP-1, CAP-2, CAP-3 (every calendar fetch() call). MUST be verified with one real end-to-end fetch() call through the actual running gateway before Story 1.2 is considered done -- not assumed from documentation alone.

- (decision) AD-16 (CAP-4, idempotency guard): before create_calendar_event issues its POST, run a list_calendar_events-style GET on the target calendar's exact requested start dateTime, filtered by that calendar's events created in the last 10 minutes. Binds CAP-4. Prevents a retried/racing create silently double-booking, and prevents an over-eager fuzzy match blocking a legitimately different event. On a match, the tool calls askUserQuestion directly in-process (same structural-confirmation pattern as delete_calendar_event, AD- Deferred entry on delete) offering 'create anyway' vs 'skip, likely already exists' -- never silently decides either way, and never trusts the agent to self-gate past it, per this project's hard-won delete_calendar_event lesson.
